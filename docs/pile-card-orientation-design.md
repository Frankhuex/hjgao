# 牌堆卡牌正逆位设计

- 状态：设计稿
- 日期：2026-09-30
- 关联文档：[counter-design.md](counter-design.md)、[in-room-chat-design.md](in-room-chat-design.md)

## 1. 目标与范围

牌堆查看器中的每张 2D 牌新增“正位 / 逆位”状态。正位按当前方向显示，逆位在 2D 查看器中旋转 180 度显示。该状态与现有 `card_ID_to_is_front` 表示的“正面 / 背面”相互独立：正面/背面决定是否显示牌名和牌面，正位/逆位决定显示方向。

2D 查看器内提供三类入口：

| 输入 | 结果 |
| --- | --- |
| 右键单张牌 | 继续执行现有翻面逻辑，切换正面/背面 |
| Shift + 右键单张牌 | 切换该牌正位/逆位 |
| 三个新按钮 | 全部正位、全部逆位、全部颠倒 |

所有从牌堆取出 3D 牌的路径都要读取正逆位。逆位牌在生成 3D 牌时给根节点增加 180 度的 Y 轴旋转；正位牌保持现有生成方向。3D 场景不新增正逆位编辑入口，也不把拖动造成的 3D 朝向变化写回正逆位状态。

本设计不改变牌堆顺序、正面/背面状态、卡组 JSON 的既有字段，也不新增排序规则。

## 2. 状态模型

正逆位保存在 `DeckInstance` 中，按牌 ID 维护：

| 字段 | 含义 |
| --- | --- |
| `card_ID_to_is_upright` | `true` 表示正位；`false` 表示逆位 |

选用全局 `DeckInstance` 映射的理由：

1. 牌 ID 在当前卡组内唯一，查看器内拖动、确认取出、放回牌堆时都可以稳定找到同一张牌。
2. 取出 3D 牌时服务器可以直接读取当前正逆位，避免在牌序数组旁再维护一份容易错位的平行数组。
3. 后加入玩家通过现有 DeckInstance 快照同步，可以自然拿到正逆位。
4. 牌堆只保存 `card_ID_stack` 顺序，正逆位与顺序解耦，排序、洗牌、拖到“即将取出”区都不会影响状态。

卡组 JSON 增加可选字段 `card_ID_to_is_upright`。字段不存在时所有牌默认正位。字段存在时校验规则与 `card_ID_to_is_front` 一致：键必须是规范正整数字符串，值必须是布尔值，且 ID 必须存在于当前卡组。

`DeckInstance.serialize_to_json()` 输出该映射。这样服务器发给晚加入玩家的认证快照会包含最新正逆位，换卡组事务的序列化/反序列化也能保持同一套格式。

## 3. 数据所有权与同步

`CardDatabase` 继续作为卡组运行时状态的唯一宿主，新增正逆位读写和广播：

| 能力 | 说明 |
| --- | --- |
| `is_upright(id)` | 读取单张牌正逆位 |
| `set_orientation(id, upright)` | 本地写入单张牌状态 |
| `orientation_changed` | 信号，携带本轮发生变化的 `Dictionary[int, bool]` |
| `sync_orientation_status(updates)` | authority + `call_local` + reliable RPC，服务器广播变化量 |

服务器只广播发生变化的牌 ID。批量“全部颠倒”最多影响 1000 张牌，当前卡组规模下可以接受。重复设置相同状态时不广播，避免按钮连点造成无效流量。

`UICard` 订阅 `orientation_changed`。收到更新后查询自己的牌 ID 并刷新旋转角度。2D UI 不做长期本地预测，最终状态以服务器广播为准；由于使用可靠有序通道，操作请求会按发送顺序落地。

## 4. 2D 查看器交互

`DeckViewerUI.tscn` 在现有正面/背面按钮附近新增一行三个按钮：

| 按钮 | 行为 |
| --- | --- |
| 全部正位 | 当前牌堆内所有牌设为正位 |
| 全部逆位 | 当前牌堆内所有牌设为逆位 |
| 全部颠倒 | 当前牌堆内所有牌逐张切换正逆位 |

“全部正位 / 全部逆位 / 全部颠倒”只作用于查看器上方的牌堆牌列，和现有“全部正面 / 全部背面 / 全部翻面”的范围一致，不作用于下方的“即将取出”区。虽然“即将取出”区的牌在确认前仍属于服务器牌堆，但批量按钮不会遍历它。操作只改正逆位，不改变本地列表顺序，也不立刻释放查看权。

`UICard` 的旋转规则如下：

1. 正位时 `rotation_degrees = 0`。
2. 逆位时 `rotation_degrees = 180`。
3. 旋转前把 `pivot_offset` 设置为控件中心，避免牌绕左上角旋转后超出布局格。
4. 正面/背面刷新逻辑保持不变。逆位正面牌的牌名也随牌面一起倒置；逆位背面牌继续隐藏牌名。
5. 悬停描述提示仍然由正面/背面控制，逆位不隐藏提示。

单张牌的 Shift + 右键处理与现有右键翻面对齐，在静置和拖动中都支持：

| 场景 | 处理 |
| --- | --- |
| 静置在查看器列表中 | `UICard._gui_input()` 在右键处理处识别 `shift_pressed`，发出单张正逆位请求 |
| 正在拖动 | `DeckViewerUI._input()` 在现有拖动右键处理处识别 `shift_pressed`，对 `dragging_card` 发出单张正逆位请求 |

两条路径都必须消费事件，避免同一次右键同时触发翻面和正逆位切换。拖动预览替身也要同步显示逆位旋转；拖动过程中收到服务器正逆位更新时，原牌和替身一起刷新。

按钮和单张操作都只发出请求信号。`DeckViewerUI` 不直接调用正逆位 RPC，而是把请求交给创建它的 `PileAccessor`，由后者结合 OwnerMux 校验并发权限。

## 5. 请求协议与 OwnerMux 并发

不需要新增 OwnerMux 用途。正逆位编辑只发生在牌堆查看器内，而查看器打开期间牌堆已经被 `Purpose.PILE_VIEW` 持续占用。复用该占用可以避免“查看锁”和“正逆位锁”互相竞争。

`Const.PileOrientationOperation` 建议定义如下：

| 枚举 | 含义 |
| --- | --- |
| `SINGLE_INVERT` | 切换单张牌正逆位 |
| `ALL_UPRIGHT` | 全部设为正位 |
| `ALL_INVERTED` | 全部设为逆位 |
| `ALL_TOGGLE` | 全部逐张切换 |

请求链路如下：

1. `UICard` 或按钮产生本地请求信号。
2. `DeckViewerUI` 转发为 `orientation_operation_requested(operation, card_id)`。
3. `PileAccessor` 连接该信号并调用 `request_orientation_operation()`。
4. 本端是服务器时直接进入服务器处理；本端是客户端时通过 reliable RPC 发给服务器。
5. 服务器校验后计算变化量，并通过 `CardDatabase.sync_orientation_status()` 广播。

服务器端校验规则：

| 检查 | 失败处理 |
| --- | --- |
| 当前节点是服务器 | 忽略请求 |
| `Util.board_locked()` 为 false | 清场或换卡组期间忽略请求 |
| 目标牌堆处于 `PILE_VIEW` 占用状态 | 忽略请求 |
| 请求发送者等于 OwnerMux 当前 owner | 忽略非 owner 或伪造请求 |
| 单张操作的 ID 存在于 `card_ID_stack` | 忽略无效 ID |
| 枚举值合法 | 忽略未知操作 |

正逆位操作不释放 `PILE_VIEW`。取消查看、断线回收、暂停菜单释放交互时，OwnerMux 会先恢复所有权；之后到达的过期请求因 owner 不匹配被服务器丢弃。查看器内的“确认取出”和正逆位请求共用可靠有序通道，因此先修改正逆位再确认取出时，服务器会按收到顺序处理。

现有右键翻面暂时保持原实现，本轮只把新增正逆位操作接入 `PILE_VIEW` 校验。后续如果要统一所有 2D 卡牌状态编辑的权限，可以把翻面也迁移到同一条 `PileAccessor` 请求链路。

## 6. 从牌堆取出时的 3D 同步

`PileCardSpawner.server_spawn_card_by_IDs()` 是所有 3D 出牌路径的公共出口。服务器在该处读取 `CardDatabase.is_upright(card_ID)`，并把结果写入新生成的 `Card`。

需要覆盖的路径包括：

| 路径 | 入口 |
| --- | --- |
| 点击牌堆本体 | `PILE_OUTPUT_TOP` 瞬时占用后出顶牌 |
| 点击“底”热点 | `PILE_OUTPUT_BOTTOM` 瞬时占用后出底牌 |
| 点击“随”热点 | `PILE_OUTPUT_RANDOM` 瞬时占用后随机出牌 |
| 牌堆查看器确认 | `PILE_VIEW` 持续占用期间把“即将取出”区作为 `drawn_card_IDs` 交给服务器 |
| 换卡组后重建牌堆 | 后续正常出牌继续读取新卡组的正逆位映射 |

3D `Card` 的根节点负责 Y 轴朝向，`Pivot` 子节点继续负责正面/背面的 X 轴翻转。两者保持独立。逆位牌生成时根节点 `rotation.y` 为 180 度；正位牌为 0 度。

为了让普通客户端和晚加入玩家看到服务器生成的初始朝向，`Card.tscn` 的 `MultiplayerSynchronizer` 增加根节点 `rotation` 的 spawn 同步。服务器在 `_ready()` 中按正逆位写入初始 Y 旋转，随后由 spawn 状态复制到其他端。正逆位只在牌堆内修改，此时对应的 3D 节点不存在，所以不需要额外的持续正逆位 RPC。

正逆位只影响从牌堆生成 3D 牌时的初始 Y 旋转，不作为 3D 拖动的持续偏移。开启自动朝向时，无论正逆位，`Dragger` 都继续按现有逻辑把牌同步为相机朝向；关闭自动朝向时牌保留当前 Y 旋转。这样逆位牌在自动朝向拖动时仍按正常方向面对玩家。牌堆和计数器不受该状态影响。

3D 拖动不会反写 `DeckInstance` 的正逆位。正逆位是牌堆内的逻辑状态；3D 场景中的相机朝向、自动朝向开关和拖动后的最终朝向都属于临时视觉状态。同一张牌之后放回牌堆时，查看器继续显示放回前的正逆位。

## 7. 生命周期

| 场景 | 正逆位处理 |
| --- | --- |
| 创建房间 | 重新加载默认卡组，映射按卡组 JSON 或默认值初始化 |
| 后加入 | 认证快照中的 `card_ID_to_is_upright` 恢复最新状态 |
| 一键清场 | 重建桌面和牌堆，并重置当前 DeckInstance 中每张牌的 `card_ID_to_is_upright` 与 `card_ID_to_is_front` 为 `true` |
| 一键清计数器 | 不影响牌堆和正逆位 |
| 更换卡组 | 使用新卡组 JSON 初始化正逆位；旧桌面状态随事务清理 |
| 玩家断线 | OwnerMux 回收 `PILE_VIEW`，查看器关闭，未落地的请求被丢弃 |
| 返回主菜单 | 清理会话节点；下次进入房间重新初始化卡组状态 |

## 8. 边界规则

| 场景 | 行为 |
| --- | --- |
| 空牌堆 | 批量正逆位操作为无操作，不广播 |
| 目标牌 ID 已不在牌堆 | 单张请求被服务器忽略 |
| 所有牌已是目标状态 | 不广播变化量 |
| 逆位 + 背面 | 牌面继续显示背面，只是背纹方向旋转 180 度 |
| 逆位 + 正面 | 牌名和牌面一起旋转 180 度 |
| 查看器内本地排序未确认 | 批量正逆位仍作用于服务器当前整堆，所有牌都会更新 |
| 确认取出前修改正逆位 | 出牌时使用服务器已确认的最新状态 |
| 非查看 owner 发送请求 | 服务器忽略 |
| 旧卡组 JSON 缺少字段 | 所有牌默认正位 |

## 10. 测试计划

解析测试：

1. 缺少 `card_ID_to_is_upright` 的旧卡组可以加载，所有牌默认正位。
2. 合法混合正逆位映射可以加载并序列化往返。
3. 未知 ID、非布尔值、非法 ID 字符串都会被拒绝。

UI 测试：

1. 查看器加载混合正逆位牌时，2D 牌分别显示 0 度和 180 度。
2. 无 Shift 右键只切换正面/背面；Shift + 右键只切换正逆位。
3. 拖动中 Shift + 右键只切换正逆位，替身和原牌同步刷新。
4. 三个批量按钮分别达成全部正位、全部逆位和逐张颠倒。
5. 批量操作不改变列表顺序，也不关闭查看器。

网络与并发测试：

1. 查看 owner 修改单张牌后，服务器和其他客户端的映射一致。
2. 非 owner 直接发送正逆位请求会被服务器忽略。
3. owner 断线后，过期请求不会修改状态。
4. 清场或换卡组期间发送请求会被忽略。
5. 同一玩家先修改正逆位再确认取出时，服务器按可靠有序通道顺序处理。
6. 晚加入玩家能通过认证快照看到最新正逆位。

取牌测试：

1. 正位牌通过顶/底/随机热点取出后，3D 根节点 Y 旋转为 0。
2. 逆位牌通过顶/底/随机热点取出后，3D 根节点 Y 旋转为 180 度。
3. 查看器把逆位牌放入“即将取出”并确认后，生成的 3D 牌带 180 度 Y 旋转。
4. 正面/背面和正逆位互不干扰；翻面仍只改变 `Pivot` 的 X 轴状态。
5. 逆位牌被拖动时，开启自动朝向仍保留 180 度相对偏移。

## 11. 验收标准

玩家在牌堆查看器中可以用 Shift + 右键或批量按钮维护每张牌的正逆位；普通右键的正面/背面行为不变。服务器只接受当前 `PILE_VIEW` owner 的修改，并把变化同步给全部客户端和晚加入玩家。所有牌堆出牌路径都会按服务器保存的正逆位生成 3D 牌，逆位牌带 180 度 Y 轴旋转。旧卡组文件无需修改即可继续使用。
