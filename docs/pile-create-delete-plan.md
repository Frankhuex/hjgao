# 空牌堆创建与删除实施计划

状态：已按用户批准的推荐方案完成实现，验证记录见第 8 节。日期：2026-10-04。

## 1. 目标与现状

在牌堆查看器 DeckViewerUI（用户所称 DeckUI）最底部增加“删除牌堆”按钮，与“关闭”放在同一 HBoxContainer 中，仅在牌堆为空时显示。在暂停菜单增加“新建牌堆”按钮。创建与删除均由服务器执行，复用现有牌堆 MultiplayerSpawner，同步给所有玩家和后加入玩家。

`DeckViewerUI.tscn` 已有 `Margin/VBox/BottomBar`，包含 `Btn_Cancel`（关闭）和 `Btn_Draw`（取出），无需另建底栏。查看器上方与“即将取出”区只是本地编辑，确认取出前服务器 `Pile.card_ID_stack` 仍包含全部牌，不能仅凭上方控件数量判断真实空堆。

`GameSession.add_pile()` 已负责实例化、preready 和加入 Piles；`Game.tscn` 的 MultiplayerSpawner_Piles 已注册 Pile.tscn。计数器创建入口 `_on_add_counter_button_pressed()` / `server_add_counter()` 当前允许所有玩家请求，服务器在有效会话且未锁定时创建。计数器删除入口 `request_delete_counter()` / `server_delete_counter()` 校验服务器、全局锁与房主/当前 owner，随后 queue_free，由 Spawner 同步销毁；CounterAccessor._exit_tree() 关闭挂在 /root 下的查看器。PileAccessor 当前缺少对应出树清理，需要补齐。

## 2. 已确认的边界

| 问题 | 推荐方案 | 对实现的影响 |
| --- | --- | --- |
| “为空”的口径（已确认） | 按服务器实际 `card_ID_stack.is_empty()`；全部移入“即将取出”区仍属于非空 | 删除独立于取牌事务，避免丢牌；取出后重新打开空堆才显示删除 |
| 创建与删除权限、可删范围 | 沿用当前计数器：所有已入房玩家可新建空堆，房主或当前查看 owner 可删任意空堆，包括公共与玩家初始堆 | 无需新增堆类别/创建者字段；玩家初始堆删除后不立即补建，清场/换库沿原流程重建 |
| 删除确认与新建行为 | 删除先弹确认框；新建复用计数器空位扫描方式，暂停菜单保持打开 | 与计数器交互一致，创建后返回游戏即可看到新堆 |

用户已明确确认服务器实际空堆口径，并授权按方案完成开发；其余采用表中推荐方案。

## 3. 交互与场景改动

DeckViewerUI 的既有 BottomBar 增加 `Btn_Delete`，文案“删除牌堆”，沿用关闭按钮字体和布局；保留取出按钮原行为。删除按钮在 tscn 中初始隐藏，载入真实空堆后显示。以绑定的 Pile 状态为准，配合两列卡牌和拖动状态检查，防止临时 UI 空列暴露删除。若查看期间收到牌堆栈更新，刷新显示条件；可给 Pile 增加轻量状态变化信号。任何显示条件都仅服务 UI，服务器必须重新检查空堆。

增加 DeleteConfirmation，文案明确“删除这个空牌堆，对全部玩家生效”；取消只关闭确认框，保留查看占用。确认后发出 delete_confirmed 信号，由 PileAccessor 转交 Pile 请求方法，UI 不直接调用服务器删除 RPC。请求发送后不提前删除本地 Pile 或直接关闭查看器，等待服务器同步结果；重复确认时避免重复请求。

暂停菜单新增 `AddPileButton`，文案“新建牌堆”，放在桌面对象操作区并检查小窗口布局。已入房显示，清场/换库忙碌时禁用；服务器仍做相同门控。创建前释放聊天焦点，保持暂停菜单现有输入冻结状态，不自动打开新牌堆查看器。

按钮 pressed 和确认框 confirmed 连接固化在相应 .tscn 中，业务组件之间的实例信号沿用现有脚本连接方式。新按钮使用已有全局 Sfx 悬停/确认钩子，无需新增音效 RPC。

## 4. 删除的服务器流程

1. 查看者打开牌堆，持有 PILE_VIEW；空堆显示删除按钮，点击并确认后由 DeckViewerUI 发信号。
2. PileAccessor 确认本地仍是查看 owner，再调用 `Pile.request_delete_pile()`。主机直接进入服务器函数，客户端经 reliable RPC 发给 peer 1。
3. `server_delete_pile()` 校验当前端为服务器、会话有效、全局锁未开启、节点尚未排队删除、服务器栈为空；通过真实 sender 识别身份，主机本地直调将 0 映射到 1。
4. 删除权限沿计数器：房主可删除；其他请求者须是当前 owner 且 purpose 为 PILE_VIEW。拒绝无占用、伪造身份、过期查看请求和非空牌堆，保持牌堆及卡牌数据不变。
5. 校验通过后服务器 queue_free。复用 MultiplayerSpawner_Piles 全网同步销毁，无需额外客户端删除广播，也不新增删除用途或锁。
6. PileAccessor._exit_tree() 幂等关闭查看器并清空引用，同时清理确认框、拖动预览与相关焦点。采用有效性检查，避免重复关闭访问已释放节点。可直接沿计数器通过销毁结束占用，避免先释放后删除产生可抢占空窗。

删除过程中不修改 DeckInstance 的 ID/正反面/正逆位，不删散牌或计数器。晚加入由服务器当前节点集合恢复，已删除堆不会重现。房主删除其他玩家当前查看的空堆时，对方查看器应跟随节点销毁关闭。若此类删除未暴露为 UI 操作，仍覆盖其服务器权限和生命周期测试。

## 5. 创建的服务器流程

1. `_on_add_pile_button_pressed()` 检查有效会话与全局锁，释放聊天焦点；主机直调，客户端发送 `server_add_pile()` reliable 请求到服务器。
2. 服务端再次检查会话和锁，并确认远端 sender 是当前已连接玩家；不接受客户端指定节点名、牌 ID 或任意位置。
3. 创建时初始 `card_ID_stack` 使用空的 `Array[int]`，通过现有 add_pile / preready 在服务器 Piles 下生成。服务器生成唯一节点名，使用独立前缀及会话内单调序号，并检查现有子节点和待删除节点，避免与“公共牌堆”、`pile<peer_id>` 及其他新堆冲突。连续/并发创建也必须唯一。
4. 沿计数器扫描桌面两侧候选位置，避开现有牌堆和计数器（现有距离阈值 2.0）；默认保留现有候选全部占满后的回退位置行为。位置在生成入树前设置，保证首次 spawn 同步已是正确位置；如需调整 add_pile 参数，保持既有调用兼容。
5. MultiplayerSpawner_Piles 复制新节点，Pile 的现有栈请求同步和 position Synchronizer 处理普通客户端及晚加入者。新堆保持现有拖动、查看、收牌和顶/底/随机交互能力。

新增堆遵循普通 Pile 生命周期：退出房间随场景清理，一键清场或换卡组会删除并沿现有流程重建标准桌面，不持久保留手工新增堆。客户端只发送请求，不本地预测生成。保持添加计数器的现有行为，避免扩大本次改动。

| 场景 | 验收结果 |

| 空牌堆打开查看器 | 删除按钮可见，与关闭处于同一 HBox；取消确认保留堆和查看器 |

## 8. 最终实现与验证记录

创建复用现有空位扫描和 MultiplayerSpawner_Piles，通过服务器单调序号生成 extra_pile_N 名称；位置在入树前设置。删除采用真实栈为空、有效会话、全局锁、房主或 PILE_VIEW owner 校验，排队删除期间重复请求直接拒绝。查看器按绑定 Pile 的 stack_changed 信号刷新删除入口，确认时再次检查查看权。未绑定实际堆的独立 UI 测试不会显示删除。正常占用下非空堆的 UI 卡牌只能在两列间移动，栈判定足以保持待取出区非空时隐藏删除，无需另行计数 UI 控件。

补齐 PileAccessor 出树清理并在 Pile 断开 multiplayer peer 或排队删除时停止拖动更新。暂停打开时显式显示 PauseCanvasLayer，兼容场景中已有的初始隐藏设置。新建按钮独立一行，避免挤压原计数器按钮。服务器的排队删除检查承担重复提交防护，没有新增长期 UI 请求锁，避免请求被拒后按钮永久不可用。

新增 tests/pile_lifecycle_test.gd 和 Python 运行器，覆盖暂停创建、唯一命名、空位、空堆显示、删除确认/取消、待抽取区不算空、忙碌拒绝、普通客户端非 owner 拒绝、owner 删除、服务器状态与后加入同步。修正 tests/deck_change_test.gd 中历史断言，将安装卡组保留面向与清场全部翻正分开验证，匹配已有生产行为。MCP 实际运行检查了新建、空堆查看、确认框、删除后的牌堆和查看器回收，并截图核实暂停布局及查看器底栏。

验证结果：Godot 4.7.2 项目解析无脚本/场景解析错误；新增生命周期测试各角色 PARSER_OK、CLIENT_OK、HOST_OK、LATE_JOIN_OK 通过，计数器回归与修正旧断言后的换库回归（含重连和后加入）通过。GUI 验证窗口为 1473×648，暂停面板和底栏均可见；更小窗口的完整手工交互未逐一验证。退出测试时偶有既有延迟名册广播在 peer 清空后执行的日志错误（_broadcast_player_roster），不涉及创建/删除断言；CLI 仍出现当前受限环境的全局编辑器设置保存错误。

音效回归另修正两处旧测试问题：sfx_test.gd 等待卡牌销毁的条件写反，以及 run_sfx_tests.py 期待 SFX_CLIENT_OK 而实际用例输出 CLIENT_OK；均只调整测试，不修改生产音效。

最终音效回归已通过，输出 SFX_PARSER_OK、CLIENT_OK、HOST_SFX_OK、HOST_ALL_OK，运行器退出码 0。

补充：暂停菜单 HBoxPiles 行加入“一键清空牌堆”，HBoxChangeDeck 行放置“更换卡组”和“一键清场”。批量空堆清理沿计数器清理请求/确认流程，由服务器在全局锁内遍历实际空栈并 queue_free，Spawner 复制销毁，等待目标节点离树后解锁。无需关闭非空堆查看器、不重建标准牌堆、不修改卡组和散牌。新增回归覆盖非空堆/计数器/散牌保留、客户端发起后服务器也仅余非空堆及确认框音效。
