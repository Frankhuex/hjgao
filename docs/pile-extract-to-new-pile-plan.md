# 待取区取出到新牌堆设计

状态：已按用户确认方案实现。日期：2026-10-04。第 1—8 节保留设计依据，第 9 节记录最终实现与验证。

## 1. 行为与默认约定

DeckViewerUI 底栏新增“取出到新牌堆”按钮，与关闭、取出和删除共用 BottomBar 的横向扩展、居中布局。待取区有牌时显示，空时隐藏；刷新时机与保存顺序按钮一致；保存顺序按钮始终显示，待取区无牌时文案为“保存顺序”，有牌时为“保存顺序并取出”，复用原确认提交链路。pressed 在 tscn 中固化。正在拖牌或等待提交结果时禁止提交。

成功后，上方列表按当前 UI 顺序成为源堆的新栈，下方待取区按当前 UI 顺序成为新堆的栈，数组前端为堆顶。新堆使用服务器生成的 extra_pile_N 网络标识，display_name 初始为空，不继承源堆名称。源堆保留，全部取出时留下空堆，后续可通过已有删除或清空入口删除。用户已确认新堆放在源堆左侧或右侧，复用取出牌的落点规则，并继承源堆朝向；不自动打开查看器。具体取待取区第一张牌在 Pile.calc_spawn_pos 中对应的 X/Z：源堆 global_position.x < 0 时向右偏移 1.12，否则向左偏移 1.12，Z 保持一致。该偏移沿世界 X 轴，与当前散牌取出一致，不随源堆旋转改变。新堆作为桌面物体使用正常落桌 Y=0，避免沿用散牌的 Card.DRAGGING_Y=0.5 悬空高度。邻近位置已有物体时沿用落点，不改为空位扫描；重叠后可手动拖开。

卡牌 ID、正反面和正逆位保持不变，不创建散牌，不改 CardSorter，不修改卡组 JSON。名称草稿不随此操作提交，之前已经确认的改名或翻面操作保留。界面在服务器确认转移成功、释放源堆占用后关闭；拒绝时保留可恢复的本地理牌草稿，并显示原因。

## 2. 当前调用链与同步依据

| 链路 | 当前源码行为 | 对新功能的约束 |
| --- | --- | --- |
| 打开查看器 | PileAccessor.request_open_viewer → OwnerMux.request_own(PILE_VIEW) → server_set_owner → _set_owner 广播 → on_owner_change → _open_deck_viewer | 查看操作持续持有源堆占用，申请返回值只表示已发请求 |
| 本地理牌 | DeckViewerUI 两列 UICard 移动、排序、抽取 n 张 | 提交前服务器栈仍含两列全部牌 |
| 现有确认取出 | _on_confirm_pressed → draw_confirmed → PileAccessor.request_viewer_operation → server_viewer_operation → server_spawn_card_by_IDs → 修改源栈 → server_sync_card_ID_stack → server_reset_owner | 新操作独立入口，直接把 ID 栈放入新 Pile；跳过散牌生成函数 |
| 新建空堆 | GameSession.request_add_pile → server_add_pile → 分配 extra_pile_N 和位置 → add_pile → preready/设置 position → Piles.add_child | 提取服务器内部命名和实例准备逻辑，支持非空初始栈与指定初始朝向；本操作位置来自源堆，暂停菜单仍沿用空位扫描 |
| 生成与补齐 | Game.tscn 的 MultiplayerSpawner_Piles 复制 Pile 节点；Pile.tscn 只复制 position；客户端 Pile._ready 请求 server_sync_card_ID_stack | preready 的栈目前不会自动随 spawn 复制，必须保留客户端栈请求及晚加入同步 |
| 关闭查看器 | server_reset_owner → _set_owner(0, NIL) → on_owner_change → PileAccessor._close_deck_viewer；Accessor 出树也会关闭 | 最后释放占用即可驱动成功关闭，不提前 queue_free 或 request_release |

现有 server_viewer_operation 仅检查全局锁和 PILE_VIEW 状态，缺少真实 sender 与 owner 比较、两列 ID 完整性校验。新入口必须补齐这些校验；实现时可让两个确认入口共用同一校验辅助方法，限定改动为查看器提交的安全性，保留原散牌取出行为。

OwnerMux._set_owner 递归切换父物体及子节点 authority，查看者为客户端时 Accessor 的 authority 也属于客户端。请求 RPC 应采用 any_peer、call_remote、reliable，并在服务器做身份校验。新增返回结果若放在 Accessor，不能直接依赖 authority 装饰来认定服务器；应采用可由服务器发送的声明并校验 remote sender 为 1，主机本地结果走直接调用。NameEditor 固定 peer 1 的规则保持原样。

## 3. 请求接口与本地等待

新增独立信号 draw_to_new_pile_confirmed(remaining_ids, extracted_ids)，PileAccessor 接入 request_extract_to_new_pile / server_extract_to_new_pile，同后缀保持语义配对。源堆由 Accessor 所属 Pile 确定，请求不接收任意目标堆、客户端位置、节点名或 owner ID。请求附带本地提交序号，失败结果回传该序号；它用于匹配当前查看器的等待状态，不承担服务器授权。

UI 从两列按实际顺序收集 Array[int]，发送前检查目标有效、当前仍为查看者、待取区非空、无拖牌、会话有效、全局锁未开启。等待期间冻结本查看器的理牌、取出、取出到新堆、删除、名称修改与普通关闭，防止重复请求或提交后的本地编辑。pending 只属于 UI 状态，不新增第二套物体互斥锁。

请求被明确拒绝时解除 pending，保留草稿；源栈已改变导致分区校验失败时提示重新打开查看器；每次重试仍执行完整服务器校验，过期分区持续被拒绝。暂停、断线、清场、换库、源堆销毁及丢失 owner 继续执行现有强制清理，不被 pending 阻挡。网络等待不自动当作成功，也不盲目重发；查看器已销毁或序号不匹配时忽略迟到结果。主机直调可能同步触发占用释放与查看器关闭，因此 pending 和序号必须在发信号前设置，回调返回后避免访问已失效的 UI。

## 4. 服务器校验

所有检查在改变栈、创建节点或释放占用前完成：当前端为服务器；GameSession 会话有效、牌库存在、源堆仍在 Piles 且未排队删除；Util.board_locked 为 false；真实 sender 为当前已入房玩家，主机直调 sender 0 映射为 1；源堆 owner 等于 sender，purpose 为 PILE_VIEW。房主同样需要当前查看占用，不能凭房主身份提交其他人的理牌事务。

待取数组必须非空。两列总长度等于服务器源栈长度，每个 ID 是当前卡组有效 ID且属于源栈，两列内部无重复、相互不交叉，合并后与服务器当前源栈的 ID 集合完全一致。检查当前服务器栈，不能只检查打开时客户端快照。允许本地重新排序，故不要求两列拼接后的顺序等于原栈。任何检查失败都保持两个牌堆和 CardDatabase 不变，并向仍存在的对应查看器返回失败原因。

接收前先完成数量上限和类型检查，采用集合或计数映射校验，避免重复 ID 被普通 has 检查放行。Array 拷贝后再写入两个堆，避免共享可变数组引用。重复请求在首次成功释放 owner 后被拒绝；按钮禁用只用于改善交互，服务端校验承担实际防护。

## 5. 锁与提交的严格顺序

1. 打开查看器时服务器已授予源堆 PILE_VIEW，占用贯穿理牌、请求发送、服务器校验与提交全过程。提交前不释放，不切换成抽牌用途，也不再次申请自己已经持有的占用。
2. 服务器首先检查清场全局锁及当前 owner。通过后，在同一个同步函数中完成准备和提交，全段无 await、deferred 提交或跨帧等待。现有栈刷新和入树回调须核实没有会重入此事务或释放源占用的业务回调；新增回调不得做这类操作。
3. 预先保存源栈副本，分配唯一节点名和位置，实例化尚未入树的新 Pile，通过 preready 注入待取栈，并在入树前设置计算好的位置和源堆当前水平朝向。准备失败直接拒绝并释放未入树对象，源堆及其占用保持不变。
4. 服务器把源栈改为上方剩余数组，随后把准备好的新堆加入 Piles。源栈先移除待取 ID，再发布目标，保证目标 _ready 看到的服务器数据已完成归属转移；新堆入树前就持有完整待取栈。避免先创建空堆、释放锁、再异步塞牌。新堆 OwnerMux 保持默认空闲，无需为新堆申请额外占用。
5. 确认入树成功后调用源堆 server_sync_card_ID_stack，广播剩余栈并刷新外观；目标通过现有 spawn 后栈请求补齐数据。整个期间源堆仍持有 PILE_VIEW。
6. 最后调用源堆 owner_mux.server_reset_owner，由可靠占用广播关闭对应查看器并恢复源堆 peer 1 authority。此调用会同步触发本机 on_owner_change，之后不再依赖 _viewer 或其控件。源堆即使为空也保留。

这次单次同步转移不设置 clear_table_in_progress，不广播全桌忙碌，不关闭其他玩家查看器。清场/换库使用全局锁，因为这些流程包含删除等待和多端确认；本操作利用既有源堆占用与服务器无 await 的提交段。对同一服务器主线程，清场请求先执行时转移被锁拒绝；转移先执行时清场会按现有流程处理转移后的两个堆。清空空堆在转移后可删除已经为空的源堆，并保留新建的非空堆。

预期资源实例化失败须在发布前解决。若新节点未成功入树，恢复源栈、回收目标并返回失败；不得先广播源栈再做可失败的准备。新节点一旦发布即视为已提交，随后以服务器状态同步和会话清理完成收敛，禁止用迟到失败结果回滚已对外发布的牌。实现应明确区分准备失败与提交完成，正常路径中无需等待客户端确认新节点到达。

## 6. 网络时序、已有边界与生命周期

Spawner 的新节点生成、源栈 RPC、owner 广播属于不同同步机制，不能仅凭服务器调用顺序承诺所有客户端同一帧看到完整转移。客户端可能先看到新堆再收到其栈，或在源栈刷新前短暂看到旧牌数；服务器数据归属在同步提交段内完成，最终由可靠栈同步收敛。关闭查看器不以本地找到新堆节点为前提，避免节点尚未到达导致永久等待。新堆的后加入恢复沿用 Pile._ready 栈请求、位置同步和 NameEditor 空名同步。Pile 当前仅复制 position，新增朝向继承需在 Pile.tscn 增加 rotation 的 spawn 初值复制，确保普通客户端和晚加入都收到服务器设置的朝向；保留 Dragger 既有旋转 RPC，不将持续 rotation 复制与其叠加。

现有 server_receive_card 会尝试占用后继续收牌，没有核实 server_set_owner 是否成功；OwnerMux.server_reset_owner 也未校验远端释放者。调研不能据此把 PILE_VIEW 宣称为所有旧 RPC 都严格遵守的服务器锁。新提交的真实 owner 和完整分区检查可以拒绝提交前已有的变化，提交段无 await 避免跨帧插入。实施时针对入堆服务器入口补上“源堆已被占用则拒绝、实际获得输入占用后才修改”的检查，作为保证本功能占用前提的必要关联修复；释放请求身份校验需覆盖合法 owner、主机内部清理和断线回收，禁止机械改变 OwnerMux 的 request_own/request_release 名称。相关修复需单独列出验证结果。

暂停若在提交请求后触发强制释放，服务器按实际接收顺序处理：释放先到则转移拒绝，转移先到则操作已成功并由暂停清理界面。失败回包不可重新打开已经关闭的查看器。断线同理，由服务器回收占用，已提交的新堆作为普通桌面物体保留。清场或换库销毁源节点时，Accessor._exit_tree 幂等回收 /root 查看器；所有按钮刷新和结果回调检查节点有效性及排队删除状态，覆盖此前 previously freed 崩溃场景。

普通按钮反馈复用 Sfx 全局钩子，新堆生命周期沿用 Pile 音效；不经过散牌生成链，不新增音效 RPC。焦点退出、查看器销毁及输入恢复继续调用现有移动动作清理，防止中文输入法遗留移动判定。

## 9. 最终实现与验证

按钮为 BottomBar/Btn_DrawToPile，pressed 固化到 _on_draw_to_pile_pressed，待取区显示刷新与 Btn_Draw 共用入口。待取列从左到右成为新堆顶到底，上方列表保留当前顺序。UI 在发信号前设置唯一提交序号和 pending、释放文本焦点并清理移动动作，通过全屏鼠标阻挡层冻结查看器操作；失败解除阻挡并显示原因，普通关闭和拖牌回调另有 pending 门控。强制暂停/离房仍走现有清理。

PileAccessor.request_extract_to_new_pile/server_extract_to_new_pile 完成源身份、全局锁、owner/purpose 和完整无重复分区校验；现有散牌确认入口也复用分区校验。GameSession.prepare_extra_pile 使用与暂停新建共用的唯一名称分配函数准备 detached Pile，待取栈先注入，位置取 calc_spawn_pos 第一张的 X/Z、Y=0，rotation 继承源堆。服务器先改源栈、加入目标、广播源栈，最后释放源 PILE_VIEW；全段无 await，无全局锁切换。新堆名称为空，源空堆保留，未调用 CardSpawner 或 CardSorter。
